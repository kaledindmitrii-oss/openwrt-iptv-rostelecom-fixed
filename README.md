# OpenWrt IPTV Ростелеком — Fixed

Независимый исправленный аналог `v1rtuozz/openwrt-iptv-rostelecom`.

**Проект НЕ является частью Universal OpenWrt.**

## Что изменено в 4.3.3

- Исправлена работа с UCI `list ports`.
- Физические Ethernet-порты определяются по `/sys/class/net/*/device`, без исключения `eth0`/`eth1` по имени.
- Установщик не меняет WAN/PPPoE.
- Без аргументов запускается простое меню.
- Добавлена пост-проверка после установки.
- Hotplug создаётся отдельным файлом `99-iptv-rostelecom` и не перезаписывает чужой hook.
- Повторная установка требует явного `uninstall`, чтобы безопасно сохранить исходное членство IPTV-порта.
- Усилена защита от ошибочной установки на bridge/VLAN/virtual interface.
- Сохраняются backup, rollback, uninstall и диагностика.

OpenWrt использует DSA на современных устройствах; для сложных VLAN-топологий OpenWrt рекомендует bridge/VLAN-конфигурацию, поэтому проект намеренно не пытается угадывать DSA VLAN-схему.

## Быстрый запуск

```sh
scp iptv-manager.sh root@192.168.1.1:/tmp/
ssh root@192.168.1.1
chmod +x /tmp/iptv-manager.sh
/tmp/iptv-manager.sh
```

Откроется меню:

```text
1) Установить IPTV (мастер)
2) Проверить IPTV
3) Диагностика / исправление
4) Показать доступные порты
5) Показать настройки
6) Создать резервную копию
7) Удалить IPTV
0) Выход
```

Для автоматизации доступны команды:

```sh
/tmp/iptv-manager.sh install
/tmp/iptv-manager.sh status
/tmp/iptv-manager.sh diagnose
/tmp/iptv-manager.sh list-ports
/tmp/iptv-manager.sh show-config
/tmp/iptv-manager.sh backup
/tmp/iptv-manager.sh restore
/tmp/iptv-manager.sh uninstall
```

## Classic IPTV

`install` рассчитан на классическую схему multicast + IGMP proxy с отдельным физическим Ethernet-портом для приставки.

Установщик:

1. определяет OpenWrt и WAN device;
2. проверяет/устанавливает `igmpproxy` через доступный пакетный менеджер;
3. показывает физические Ethernet-порты;
4. просит выбрать IPTV-порт;
5. создаёт backup;
6. убирает выбранный порт из существующего bridge через UCI list-операции;
7. создаёт `br-rt-iptv` с IGMP snooping;
8. создаёт `rt_iptv_lan` и DHCP;
9. создаёт отдельные firewall zones/rules;
10. настраивает `igmpproxy`;
11. применяет конфигурацию и выполняет пост-проверку.

WAN credentials и PPPoE установщик не изменяет.

## VLAN

Если конкретная схема Ростелекома требует VLAN, VLAN ID должен быть известен заранее.

Пример старого/простого L2 parent:

```sh
/tmp/iptv-manager.sh install-vlan eth0 100 lan4
```

`100` — только пример. Проект не утверждает, что это VLAN Ростелекома.

Для DSA-схем, где VLAN должен быть построен через `br-lan.<VID>`/`bridge-vlan`, используйте штатную UCI/LuCI-конфигурацию OpenWrt. Не переносите пример `eth0.<VID>` на DSA-роутер вслепую. OpenWrt прямо описывает различия между legacy swconfig и DSA.

## Multicast source / altnet

В проекте сохранён стартовый набор source IP из исходного аналога. Он не считается универсальным для всех регионов.

Добавить источник:

```sh
/tmp/iptv-manager.sh add-altnet 212.12.12.236
```

Удалить источник:

```sh
/tmp/iptv-manager.sh remove-altnet 212.12.12.236
```

Не следует без необходимости разрешать весь IPv4 диапазон как `altnet`: смысл `altnet` — ограничивать допустимые multicast sources.

Полезные системные команды:

cat /proc/net/igmp

## IGMP version

По умолчанию проект больше не принудительно задаёт IGMPv2. Если конкретная линия/оборудование требует IGMPv2, запускайте установщик так:

```sh
IGMP_VERSION=2 /tmp/iptv-manager.sh install
```

Допустимы `1`, `2` и `3`. Пустое значение оставляет поведение bridge по умолчанию.

## Автоматический rollback

Автоматический rollback после ошибки установки теперь удаляет только созданные проектом UCI-секции, возвращает исходное членство IPTV-порта и пользовательский hotplug. Он не восстанавливает целиком `/etc/config/network`, `/etc/config/firewall`, `/etc/config/dhcp` или `/etc/config/igmpproxy`.

Команда `restore` остаётся отдельным аварийным **полным** восстановлением сохранённых файлов и должна использоваться осознанно.

## Backup / rollback

Перед установкой создаётся backup:

```text
/root/iptv-rostelecom-backups/
```

Восстановление:

```sh
/tmp/iptv-manager.sh restore
```

`restore` заменяет сохранённые целиком файлы `network`, `firewall`, `dhcp`, `igmpproxy`. Используйте его именно как аварийный rollback к состоянию backup.

`uninstall` удаляет только секции проекта и не делает полный откат пользовательских изменений.

## Важные ограничения

- Это не официальная конфигурация Ростелекома.
- Multicast topology может отличаться по региону, доступу и оборудованию.
- Не угадывается VLAN ID.
- Полную IPTV-проверку нельзя выполнить без реального OpenWrt-роутера и действующего подключения.
- `192.168.100.1/24` используется только как локальная сеть для выделенного IPTV-порта. В Classic upstream берётся из существующей `network.wan`; второй L3-адрес на WAN не создаётся. В VLAN mode адрес upstream получает отдельный VLAN-интерфейс по DHCP с отключённым default route/DNS.

## Для обычного пользователя

Рекомендуемый путь — запуск без аргументов:

```sh
/tmp/iptv-manager.sh
```

Мастер показывает найденный WAN и физические порты, сохраняет резервную копию и только затем меняет IPTV-конфигурацию. Не вводите VLAN ID наугад: если Ростелеком использует VLAN, его нужно узнать для вашего региона и схемы подключения.

Если интернет работает через PPPoE/VLAN, не выбирайте Classic только потому, что он проще: upstream IPTV может требовать отдельный VLAN/DSA bridge. В такой топологии сначала настройте штатный DSA bridge/VLAN через LuCI/UCI и не переносите `eth0.<VID>` на современный DSA-роутер вслепую.


## Важное про режимы

Classic использует существующую сеть `wan`; VLAN настраивается только с явно указанным parent/VLAN ID. DSA VLAN не угадывается.

## Что проверяет 4.3.3

- Classic больше не создаёт дублирующий UCI-интерфейс на физическом WAN и не требует, чтобы WAN device был физическим: PPPoE/VLAN logical `network.wan` не блокируются.
- Перед изменением конфигурации выполняется проверка конфликтов имён проектных UCI-секций.
- Backup создаётся до изменения состояния выбранного порта и хранит состояние проекта/hotplug.
- При критическом сбое rollback восстанавливает конфигурацию и проектный hotplug.
- `add-altnet`/`remove-altnet` поддерживают IPv4 и IPv4/CIDR и не создают дубликаты.
- `plan` позволяет посмотреть топологию и ограничения без внесения изменений.
- DSA VLAN не угадывается: OpenWrt использует `bridge-vlan` для DSA, поэтому сложная VLAN-топология должна быть задана по фактической схеме провайдера.


## Пользовательский сценарий 4.3.3

Для первого запуска рекомендуется меню без аргументов. Перед изменением конфигурации мастер показывает физические порты, состояние линка и текущее bridge-членство выбранного порта, затем просит подтверждение. Backup создаётся до изменения сети.

`restore` — аварийная полная замена файлов из backup. При обычной отмене/ошибке установки используется проектный rollback, который не заменяет целиком пользовательские конфиги.
